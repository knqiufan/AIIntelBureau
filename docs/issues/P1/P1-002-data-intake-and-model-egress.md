# P1-002：自由输入 PII 边界和模型数据出境控制不足

- 状态：Closed（2026-07-23）
- 分类：隐私 / 第三方数据处理
- 优先级：P1

## 已证实证据

- `backend/app/services.py:211-223` 仅检测大陆手机号、身份证号和可配置词；
  邮箱、银行卡格式、非大陆号码、真实地址变体等不会被可靠阻断。
- `backend/app/domain.py:146-162` 允许耳语与提问正文进入内存、检索 trace 和模型调用。
- `backend/app/memory.py:168-175` 将记忆写入/检索外部 PowerMem/SeekDB；
  `role_responder.py:249-270` 将已过滤但仍属私有的证据正文发送给兼容 OpenAI 的 LLM。

## 影响

“明显 PII 拦截”不等于数据分类或合规控制。现场人员可输入未覆盖的敏感内容，随后
可能被持久化、嵌入并发送至第三方模型端点；项目未记录处理目的、保留期或供应商边界。

## 修复方案

1. 将演示输入设计为受控剧本优先；生产/公网默认关闭自由耳语，需显式批准才开启。
2. 引入分层 DLP：格式规则、词典、长度/熵检测、人工确认或拒绝策略；拒绝路径不回显原文。
3. 为 LLM、embedding、数据库分别定义数据分类、地域、供应商、保留期和删除契约；
   未获批准的数据不得出境。
4. 增加 `DEMO_DATA_RETENTION` 的运维说明和按 case 的删除证明；对外部删除失败提供补偿队列。

## 验收标准

- 代表性邮箱、电话号码、银行卡、地址、身份证和提示注入样例均按策略拦截或需要确认。
- 禁用自由输入时，所有写入口（含高级功能）都无法绕过。
- 每个外部调用可从配置和文档确定数据类型与目的，日志不记录原文。
- 删除 case 后可验证本地账本、记忆库及外部处理任务的状态。

## 待验证

供应商是否存储 prompt、向量或日志取决于真实账号和合同，必须由运维/法务确认。
本 issue 不应声称现有服务已经泄露到第三方，只记录代码存在数据出境路径。

## 修复记录

自由耳语默认关闭；启用时 DLP 拦截邮箱、国际电话、支付卡、身份证、地址信号与提示词注入。LLM/embedding 出境必须显式审批，含自由耳语的命中保持本地确定性回答。复测：`test_p1_hardening.py`。
