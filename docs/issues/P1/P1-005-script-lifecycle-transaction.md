# P1-005：剧本切换和加载失败破坏案件一致性

- 状态：Closed（2026-07-23）
- 分类：领域状态机 / 远端写入一致性
- 优先级：P1

## 已证实证据

- `backend/app/services.py:160-176` 对不同 `script_id` 直接循环写入新私有卡，
  只在全部完成后更新 case；不会删除旧角色空间或公告板内容。
- 同一文件 `169-174` 在第 N 张卡写入失败时无回滚；case 仍可能是 `empty`，
  但远端已经存在部分卡片。重试会继续追加。
- 前端角色栏允许选择多个剧本；mock 也按追加方式实现，说明该语义未被明确禁止。

## 影响

从 password 直接切换 mole/allergy 会混入旧私有情报和旧公开副本，检索结果与
`case.script_id` 不一致。远端短暂失败还会产生孤儿卡、重复种子和难以解释的演示结果。

## 修复方案

1. 写出案件状态机：`empty -> loading -> ready -> resetting`；定义“切剧本”是拒绝、
   强制 reset，还是原子替换，不能保持隐式追加。
2. 若支持替换，先清理或隔离旧 epoch，再写入新 epoch，提交 case 状态前验证完整性。
3. 将已成功写入的卡片记录为补偿集合；加载失败时按 case+epoch 删除并保留安全错误事件。
4. 远端无法提供事务时，采用 outbox/saga 或加载版本号，确保重试幂等且不会读到半成品。

## 验收标准

- password 后加载 mole 要么返回明确冲突并要求 reset，要么只留下 mole 的预期空间。
- 模拟第二张种子写失败后，远端与本地均无半成品，重试不会出现重复卡。
- snapshot、审计、SSE 和 UI 对 `loading`/失败状态有一致展示。
- 测试覆盖切换、超时、部分失败、补偿失败和重试。

## 依赖与观测

与 P1-006、P1-007 共同确定远端记忆的一致性模型。观测仅记录阶段、计数、case/epoch
和失败类型，不能写入种子正文。

## 修复记录

案件显式经过 `empty → loading → ready`；切换剧本必须 reset。加载失败会反向删除已写入卡片，远端补偿失败保留任务证据；加载仍只增加一个公开版本号。复测：`test_script_load_failure_compensates_written_cards`。
